# Domain docs

## Before exploring

Read the root `CONTEXT.md` and the ADRs under `docs/adr/` relevant to the work. This is a single-context repository. If a required domain document is absent, proceed silently; domain-modeling can create it when a term or decision is resolved.

## Vocabulary

Use the glossary's terms in specs, tickets, hypotheses, tests, and implementation descriptions. For a missing concept, first check whether an existing term applies; record a real gap for domain-modeling.

## Decisions

Respect applicable ADRs. Explicitly identify any proposed conflict and its reason instead of silently overriding an architectural decision.
